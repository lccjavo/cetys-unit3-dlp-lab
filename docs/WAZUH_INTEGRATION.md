# Optional: Centralizing DLP Events with Wazuh (Conceptual)

This lab does **not** require installing Wazuh. This page explains how the events
generated by the lab could feed a centralized monitoring platform.

## Roles

| Component | Role |
| --- | --- |
| **DataFog Core** | Identifies personal information (email addresses, phone numbers) |
| **Gitleaks** | Identifies exposed secrets in files and Git history |
| **The application / Git hook** | Enforces the preventive action (block, anonymize, reject commit) |
| **Wazuh** | Receives, correlates and alerts on the security events |

## Events produced by the lab

Every DataFog operation and every `scripts/scan_secrets.py` run appends one JSON line to
`output/dlp_events.jsonl`. The events contain **types and counts only**, never the
detected values or secrets:

```json
{"timestamp": "2026-11-02T22:10:57+00:00", "source": "cetys-dlp-lab", "tool": "datafog", "action": "export_blocked", "file": "sensitive_customers.csv", "records": 8, "findings": {"EMAIL": 10, "PHONE": 9}}
{"timestamp": "2026-11-02T22:11:05+00:00", "source": "cetys-dlp-lab", "tool": "gitleaks", "action": "secrets_detected", "mode": "dir", "findings": {"cetys-lab-token": 1}, "files": ["config.py"]}
```

## How Wazuh would collect them

1. **Agent:** the Wazuh agent on the workstation or CI runner monitors the file
   (`ossec.conf`):

   ```xml
   <localfile>
     <log_format>json</log_format>
     <location>/path/to/cetys-unit3-dlp-lab/output/dlp_events.jsonl</location>
   </localfile>
   ```

2. **Decoding:** the manager decodes each line with the built-in JSON decoder, so fields
   such as `tool` and `action` become searchable.

3. **Rules:** custom rules (in `local_rules.xml`) turn events into alerts, for example:

   ```xml
   <group name="dlp,">
     <rule id="100500" level="10">
       <decoded_as>json</decoded_as>
       <field name="source">cetys-dlp-lab</field>
       <field name="action">export_blocked</field>
       <description>DLP: export of personal data blocked</description>
     </rule>
     <rule id="100501" level="12">
       <decoded_as>json</decoded_as>
       <field name="source">cetys-dlp-lab</field>
       <field name="action">secrets_detected</field>
       <description>DLP: secret detected by Gitleaks</description>
     </rule>
   </group>
   ```

4. **Correlation:** Wazuh can relate events by host, user and time. For example, it could
   flag several blocked exports from the same machine in a short period, or a detected
   secret followed by a push to the repository.

## Design principle

A monitoring system must not become a new leak. Send **metadata** (what type, how many,
where, which rule) and keep the sensitive values out of logs, as these events do.
